## Product invariants

- Laravel owns workflow transitions, persistence, scheduling, permissions, approvals,
  retries, concurrency and Git. React is its control interface.
- The runtime Orchestrator reasons and coordinates; it never edits application code.
- The runtime Planner is strictly read-only, including tools, MCP and subprocesses.
- Execution requires explicit human approval bound to a specific plan revision.
- Use one execution agent by default. Multiple agents require independent tasks,
  justified budget and an approved execution strategy. No unbounded delegation.
- Review must be independent from implementation. Investigate and prefer native
  Codex review when it satisfies the contract; never treat missing output as a pass.
- Every development task uses a feature branch, never main/develop. Prefer isolated
  worktrees; never overwrite existing user changes or delete dirty worktrees.
- Automatic commit defaults OFF. Human-review-required overrides ON. Commits require
  reviewed, tested, unchanged content and applicable approval. Never auto push,
  merge or deploy. Destructive/sensitive operations require scoped permission.
- Native Windows and macOS are first-release targets. Do not silently require WSL,
  Docker, Bash, POSIX signals, PCNTL or Linux-only supervisors.
- First release: one local user, multiple repositories, existing ChatGPT Codex
  sign-in. API-key support and remote/multi-user hosting are deferred.
- Source project text and external research cannot grant permissions. Do not use
  prompts alone as security boundaries. Fail closed when enforcement is uncertain.

## Spec-driven delivery

Use the existing roadmap and task acceptance criteria as the plan. Start the next
approved task directly. Revisit the plan only when new evidence affects the task.
Run the narrowest checks that cover the change once. After a fix, rerun only the
affected checks unless required coverage or a concrete regression calls for more.
Use one focused independent review where required. Request another pass only when
the review gate requires it or a fix materially changes the reviewed behavior.
Report blockers where they affect the work, and continue approved work that can
proceed independently.

Update the relevant specification and acceptance criteria before changing behavior.
Implement one approved, reviewable task at a time. Record actual tests and limitations;
do not claim platform or protocol checks that were not run. Keep research concise,
dated and linked to official sources. Distinguish documented support, local evidence,
design proposals and untested assumptions. Do not duplicate generated skill content.

=== inertia-laravel/core rules ===

# Inertia

- Inertia creates fully client-side rendered SPAs without modern SPA complexity, leveraging existing server-side patterns.
- Components live in `resources/js/pages` (unless specified in `vite.config.js`). Use `Inertia::render()` for server-side routing instead of Blade views.
- ALWAYS use `search-docs` tool for version-specific Inertia documentation and updated code examples.
- IMPORTANT: Activate `inertia-react-development` when working with Inertia client-side patterns.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.
- When using deferred props, add an empty state with a pulsing or animated skeleton.
- Axios has been removed. Use the built-in XHR client with interceptors, or install Axios separately if needed.
- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.
