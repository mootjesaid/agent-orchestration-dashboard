## Objective

Create safe per-task branches/workspaces through a trusted boundary.

## Scope and relevant areas

repository/workspace actions; Git adapter; private storage settings (proposed).
Check existing siblings and the [architecture](../docs/ARCHITECTURE.md) before selecting final file names.

The approved slice exposes trusted Artisan commands for preparing a standalone
clone and inspecting its tracked diff and untracked paths. The caller supplies
an existing dedicated workspace root, the exact base commit, and a feature
branch. Provisioning uses the local repository only and retains failed clones
for inspection. Executor access and commit authorization remain gated.

```text
php artisan git-broker:prepare "<repository>" "<workspace-root>" "<full-commit-hash>" "feature/<task>"
php artisan git-broker:inspect "<workspace-root>" "<prepared-clone>" "<full-commit-hash>" "feature/<task>"
```

Only trusted local operators may invoke these commands. Provisioning uses the
configured Laravel cache lock, which must be shared by local broker processes.
Inspection returns the tracked diff and the paths of untracked, non-ignored
files. It compares the working files with the approved base using a fresh index.
If the snapshot contains non-UTF-8 bytes, the JSON marks the diff and paths as
base64. Prepare requires the base commit to be reachable from a local branch.
Inspection does not produce approval evidence for a commit. The workspace root
is selected per invocation for the existing trusted commands.

The trusted broker includes durable registration. A local operator registers a
canonical repository and chooses a dedicated workspace root. Registered prepare
uses the stored root and revalidates the repository root and common Git directory
before cloning. Under the broker lock, preparation refreshes canonical paths
and verifies the filesystem identities recorded at registration. Windows uses
local filesystem file IDs. Duplicate registrations require a future update flow.
Registration rejects overlap between a workspace root and any registered
repository root or common Git directory. Registered prepare rechecks that
separation before cloning.
All prepare commands must respect registered repository and workspace
boundaries. Registration and preparation share a broker lock so the registered
boundaries cannot change during clone preparation. Clean, dirty and partially
provisioned task clones are retained indefinitely under the operator-selected
root. Any removal requires separate explicit approval. Q04 and executor isolation
proof remain open.

```text
php artisan git-broker:register "<repository>" "<workspace-root>"
php artisan git-broker:prepare-registered "<registration-id>" "<full-commit-hash>" "feature/<task>"
```

## Acceptance criteria

- [x] Validate canonical repository/common-directory identity and user-approved workspace root for registered preparation.
- [x] Create a standalone local clone and task feature branch from the explicit base. Verify private Git metadata and object storage and refuse main/develop work.
- [x] Preserve source dirt, reject overlapping roots and unexpected task branch/base, and serialize broker registration and clone preparation.
- [ ] Prove that Git writes are brokered and that executor writes cannot reach clone metadata, the registered repository, or other protected locations.
- [ ] No implicit fetch/reset/clean/remove; dirty workspaces retained; resolve Q04.

## Validation and handoff

The shared preparation lock and ad hoc overlap guard passed Pint, PHPStan for
the broker, and 11 broker tests (47 assertions) on Windows PHP 8.5.12.
A focused independent review found no actionable regressions in those changes.

On Windows PHP 8.5.12, the registration and identity changes passed Pint,
PHPStan, and nine broker tests (42 assertions). The independent follow-up review
found a cross-repository overlap gap. After the fix, Pint and the single overlap
regression test passed (three assertions).

On Windows PHP 8.5.12, Pint and PHPStan passed. All 67 Laravel tests passed
with 277 assertions, including five broker fixture tests. They cover
both Artisan commands, source dirt preservation, primary branch and overlapping
root rejection, inspection after index flag changes, lossless non-UTF-8 output,
and rejection of changed branches and unreachable bases. A read-only independent
review identified the object storage, index, base availability and encoding gaps
addressed by the broker. macOS and OS-level isolation remain open.
