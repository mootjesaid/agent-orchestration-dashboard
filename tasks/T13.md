# T13: Single-agent scheduling and assignment

Status: proposed, not approved or started. Updated 2026-11-18.

- Dependencies: T06, T07, T08, T12.
- Requirements: FR07, FR12, FR14 in [PRD](../docs/PRD.md).
- Complexity: M (relative uncertainty, not a delivery promise).
- Agent recommendation: one executor using an available capable model, high effort;
  independent reviewer afterward. No parallel agent work by default.

## Objective

Assign approved ready tasks with one active slot by default.

## Scope and relevant areas

scheduler/actions; task dependencies; assignment records (proposed).
Check existing siblings and the [architecture](../docs/ARCHITECTURE.md) before selecting final file names.

## Acceptance criteria

- [ ] Only approved ready DAG tasks reserve a slot; dependency failures block downstream tasks.
- [ ] Enforce global cap across repositories, retries and all roles.
- [ ] Assignment contains full approved contract, context, workspace, model/effort and limits.
- [ ] No hidden native delegation; unsupported choices fail visibly.
- [ ] Pause/budget/lease/policy changes stop new dispatch; resolve Q05 defaults.

## Validation and handoff

Concurrent scheduler, dependency, stale-context and budget admission tests.
Record exact checks, outcomes and limitations. Update specification/decision evidence and
project memory. Required checks must pass before independent review; no tests or capability
proofs have been run merely because this task exists.

## Excluded scope and budget

No unrelated features, dependency upgrades or scope expansion. Installation, native sandbox
setup and new dependencies need specific approval. Budget: one focused task/role session;
record estimated token/time range and confidence before dispatch. Numeric estimates remain
unknown until T01-T03 establish measurements. Split L tasks at the named boundary before
implementation approval if they cannot be reviewed independently.
