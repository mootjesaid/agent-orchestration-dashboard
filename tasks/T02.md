## Acceptance criteria

- [ ] Read-only role enforcement through shell, tools, MCP and child processes.
  - [x] Basic shell read and create/edit/delete denial; one child write denial.
  - [ ] Full tool, MCP and child-process coverage.
- [ ] Executor isolation and an enforced Git broker boundary.
  - [x] Both disposable Git config writes denied; Windows Sandbox protected a read-only fixture mapping.
  - [x] App Server launched inside the disposable clone allowed a workspace write and denied writes to the source sentinel and both Git configs.
  - [x] Writes to disposable orchestrator-state and secret files, another repository, and a source file reached through a junction were denied.
  - [ ] Enforce read isolation for secrets and private state. The native workspace-write sandbox read the outside synthetic secret successfully, even with App Server launched inside the clone.
- [ ] Path, network and inherited configuration checks.
  - [x] One read-only subprocess check used a path with spaces and Unicode.
  - [x] A write through a Windows junction into the source fixture was denied.
  - [ ] Verify other path redirects, drive boundaries and inherited configs/hooks.
  - [ ] Enforce and verify network denial. A read-only sandbox command connected to a disposable host loopback listener with `networkAccess: false`.
- [ ] Native process lifecycle.
  - [x] Bidirectional PHP stdio and EOF, bounded output, active model-turn interrupt, clean thread resume across App Server processes, and synthetic process-tree stop.
  - [x] A scoped Windows process-tree stop removed the native App Server and both command processes in the disposable fixture.
  - [ ] Verify interruption during a tool, clean exit, terminal close, sleep/wake and restart recovery.
- [x] Record the tested Windows build and keep execution blocked on a failed core guarantee. macOS evidence is deferred to release validation.

The remaining matrix includes MCP and inherited configuration isolation,
shared Git metadata and broker enforcement, path redirects and drive boundaries,
network denial, interruption during a tool, native Codex process-tree cleanup,
terminal exit, sleep/wake, and native macOS. The read-only sandbox checks are
limited to the exercised disposable paths.

The standalone Windows clone probe verified separate Git metadata and denied
writes to both Git configs. Initially, App Server started in the source
repository and the outside sentinel was writable. Starting App Server inside
the clone denied that outside write while preserving the in-clone write.

After the host restart, the disposable Windows Sandbox folder-mapping probe
passed on Windows 11 Pro build 26300.9711. The guest read the protected sentinel
and its write attempt was denied. The host confirmed that the protected file
retained its original contents and the working file changed. This covered two
mapped fixture folders. Full role, Git broker and Codex lifecycle checks remain
open, and executor writes remain gated.

The native App Server rejected streaming and `command/exec/terminate` for
Windows-sandboxed commands. A scoped `taskkill /T /F` stopped the owned App
Server and both fixture command processes in 157 ms. Clean stdin-close
shutdown of an active command remains unproven. See the [capability results](../docs/CAPABILITY-VALIDATION.md).
